# Fidelity: our game against the original's recording

The investigation recorded the original playing MP_2P_Storm_Coast with the
default set-up (evidence E-trace-002): player 0 a
human who gives no command, player 1 the computer of the default slot strength
0, which plays profile 1 (Weak; UI-SETUP-2.5, Q-275), start resources Medium.
We play the same game (`tests/traces/README.md`), and `trace-diff` compares
the two tick by tick: every settler by place, every building, and the
simulation's random generator (`docs/trace-format.md`). The generator row is
the strictest check. Its state and draw index match only when every system
of the game drew as often as the original's in every tick so far
(SIM-RNG-2.5, `docs/rng-diff.md`).

This page records how close we are. Every commit shows whether we moved
closer:

```bash
cargo run --release -p s2-app -- fidelity
```

That command makes our traces from the program as it is (about 30 s; it
needs the game data, `S2_GAME_DIR`, and the recordings), prints the measures
and compares them with the record below. The test
`fidelity::tests::no_earlier_difference_than_recorded` does the same in a
release build (`cargo test --release -p s2-app fidelity`; a debug build leaves
it out as too slow). It never fails because the games differ. It fails only
when a first differing tick moves earlier than recorded, which is a
regression. A commit that moves a tick later writes the new block here, in the
same commit.

The recordings of the original (`specs/traces`) are not in the public copy
(`docs/releasing.md`, "The public copy"): there the measure cannot be made,
and the record below is the working repository's.

What runs where:

| Check | The public CI (GitHub's hosted runners, every push and pull request that changes more than Markdown files) | The maintainer's machine (the game installed, the recordings, a desktop) |
|---|---|---|
| formatting, Clippy, `cargo test --workspace` | yes; the tests that need the game or the recordings skip | yes, with the game and the recordings, before every release |
| the fixture games' state hashes, the same on Linux and Windows; short soaks | yes | yes |
| the golden state hashes of the install's maps (`scripts/golden.sh`) | no | before every release |
| `s2-app fidelity` against the recordings (this page) | no | on every push to the working repository, and before every release |
| the golden pictures and the play harness | no | before every release |
| the picture comparison (below) | no | when a release measures it again |

## The measures

- `first-differing-tick`: the first tick in which any row of the first pair
  differs, its settlers compared without the animation column (E-trace-002's
  view lag, above; with it the first pair's first differing tick was 1762,
  a lag of the recorder and not a difference). `s2-app fidelity` prints
  `without: animation` under that pair, and `scripts/metrics.sh` writes it
  as the pair's `without`.
- `settlers-`, `buildings-`, `generator-first-differing-tick`: the same per
  kind of row. The generator's comes from the second pair, which covers
  150 000 ticks.
- `generator-matching-ticks`: the ticks of the second pair whose generator
  rows are equal. Equal rows mean equal draw counts. Once the counts part
  they meet again only by chance, so this count grows mostly when the first
  difference moves later.
- `generator-compared-ticks`: the ticks of the second pair compared.
- `one-player-first-differing-tick`: the first tick in which any row of the
  third pair differs.
- `one-player-generator-first-differing-tick`, `-matching-ticks`,
  `-compared-ticks`: the generator measures of the fourth pair. With no
  castle in the east and no computer player these are the animals' draws
  alone. The original's settler rows from 27 742 on have some rows with an
  empty animation, written while its window raced (Q-325); they do not
  count before the generator's first difference.
- `dense-first-differing-tick`, `dense-settlers-`, `dense-buildings-`,
  `dense-generator-first-differing-tick`, `-matching-ticks`,
  `-compared-ticks`: the same measures on the fifth pair, the dense
  recording. Its game is the first pair's (the generator agrees with the
  150 000-tick recording in every tick), so its first differences are the
  first pair's until one lies past 5000, where the first pair has only every
  10th tick.
- `dense-20000-first-differing-tick`, `dense-20000-settlers-`,
  `dense-20000-buildings-`, `dense-20000-generator-first-differing-tick`,
  `-matching-ticks`, `-compared-ticks`: the same measures on the sixth pair,
  E-trace-011, the dense recording past 6000 (every tick from 5500 to
  20 000). Its game is again the first pair's, so it says tick for tick
  where the games part after 6000; the settlers are compared with the
  animation column, as nothing shows a lag of this recorder (Q-366 a asks
  about one view tick, 6228).
- `dense-40000-first-differing-tick`, `dense-40000-settlers-`,
  `dense-40000-buildings-`, `dense-40000-generator-first-differing-tick`,
  `-matching-ticks`, `-compared-ticks`: the same on E-trace-014, the
  Weak game again, every tick from 20 000 to 32 000, its settlers without
  the animation column. It says tick for tick where the Weak game parts
  past 20 000 (its first record, 2026-10-28: settlers 22214, buildings
  22730, generator 22219). Our default trace runs to 40 000 for it (31 MB).
- `hard-20000-first-differing-tick`, `hard-20000-settlers-`,
  `hard-20000-buildings-`, `hard-20000-generator-first-differing-tick`,
  `-matching-ticks`, `-compared-ticks`: the same measures on the seventh
  pair, E-trace-012, the game with a Strong computer player (profile 3). It
  is a game of its own: the original's differs from the Weak game from trace
  tick 300 (settlers), 1240 (buildings) and 1380 (generator), so it measures
  the rules of profile 3 (its baseline of 2026-10-27: settlers 300,
  buildings 1610, generator 1520). Nothing may move earlier on it either.
- `hard-150000-first-differing-tick`, `hard-150000-settlers-`,
  `hard-150000-buildings-first-differing-tick`: the same on the long Hard pair,
  E-trace-013, the Hard game to 150 000 at every 10th trace tick to
  40 000 and every 100th after, its settlers without the animation column.
  `hard-150000-generator-first-differing-tick`, `-matching-ticks`,
  `-compared-ticks`: the generator measures of the ninth pair, E-trace-013's
  generator rows of every tick, as the second pair's for the Weak game. Its
  first record (2026-10-28): 9780 (buildings), settlers 9790, generator 9784
  (9 848 of 149 993 ticks matching), the Hard 20 000 pair's points.

`none` means no difference.

## The picture comparison

The look comparison ([`docs/compare.md`](compare.md)) shoots 12 scenes of
the Storm Coast game in both programs, from the original's camera at the
same tick (ticks 1,500 and 6,000 by day, 11,000 at night; with and without
the fog), and `s2-app look-measure DIR --masks MASKS` measures the mean
colour of fixed regions in each, the water by the depth of the ground under
it. A region passes when each colour channel is within 3 % of the
original's, or, with the dark bound, within one level of 255 where the
original's mean is below 30. One region has too few samples to judge.

| Date | Release | Regions judged | Within 3 % | Within 3 % or the dark bound |
|---|---|---|---|---|
| 2026-11-12 | before 0.9.2 | 62 | 52 | 62 |
| 2026-11-14 | 0.9.6 (the game as in 0.9.5; 0.9.7 draws the same) | 62 | 52 | 62 |
| 2026-11-15 | 0.10.1 | 62 | 52 | 62 |

The same regions pass and fail on 2026-11-15 as on 2026-11-14. Off by more
than 3 %: at night the grass, the paving, the
headquarters' dome, the shore's film and the shallow water (3 to 7 %); by
day the blue of the grass (4 % in the open, 11 % in the farm's shade).
